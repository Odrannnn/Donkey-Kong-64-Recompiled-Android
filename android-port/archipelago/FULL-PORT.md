# Full randomizer port: implementation status

The full DK64 Randomizer campaign is **not playable yet**. The direct Android client still accepts only the separate five-move/two-check integration-test world. Nothing here requires a desktop relay. Do not use the test package with ordinary DK64 Archipelago seeds or existing campaign saves.

The reference is `2dos/DK64-Randomizer` commit `66d0dc90064a572e9bf2a2eada53ef81a7f47eb4`, Archipelago world version 1.5.8. `generated/port-coverage.json` records source locations for the remaining work; it is not a compatibility certificate.

| Detectors | All 291 stock-flag candidates execute in the guarded ledger; 120 shop entries have purchase-event handlers; 290 enemy and 167 explicit-event entries are catalogued | Enemy drops, new/repurposed flag hooks, Helm and goal callbacks |
| Items | All 184 client definitions; generated bounded effect plans, receipt-derived inventory and original-`CountStruct` query semantics, an exact one-receipt MIPS transaction proof, and a dormant recoverable commit for 148 definitions, including five trap behaviors represented by 13 aliases | Port the other 11 trap behaviors represented by 17 definitions; connect remaining query categories and notifications to gameplay |

`CampaignCatalog` verifies the embedded catalog digest before interpreting effect metadata. Its inventory is separate from both checked locations and spendable game counters. The pinned-source compiler also normalizes every definition into at most two fixed game-side operations. `mod/campaign_inventory.c` rebuilds a 252-byte derived ownership snapshot from a complete durable receipt prefix and publishes it only when every item is known and supported. It covers combined effects, progressive caps, fallback flags and all 16 trap classes without executing JSON in the game. `mod/campaign_inventory_stage.c` accepts that prefix only while all gameplay capabilities are zero and only when its length, seed binding and counter exactly match the CRC-protected trailer. Snapshot reads revalidate the current file and trailer, so changing or restoring a save cannot expose stale ownership. The C reducer and native JSON model are compared after every supported catalog entry; the real linked MIPS implementation exercises staging, reset, identity changes and atomic failure paths. Legacy/event item definitions with no upstream client delivery effect remain explicitly unsupported and cannot be starting inventory. This distinction prevents falsely treating every catalog entry as a grantable item.

`CampaignChecks` reports only seed-selected locations. The matching `mod/campaign_checks.c` ledger copies and validates a complete selected/restored snapshot only while every gameplay capability is zero, then accepts exact AP event IDs or the 291 catalogued stock-flag candidates only behind its dedicated capability. Every operation revalidates the current file and the full CRC-protected campaign trailer identity. Restoration is additive, failed replacements are atomic, and a changed or foreign save immediately makes observations and snapshots unavailable. A shared shop excludes all five individual Kong shops at that vendor/level, even though only the Donkey flag numerically aliases it. Both host and game validators enforce this. Flags from `0x26B` onward include randomizer additions and repurposed flags: polling those in a stock save is unsafe, so the dispatcher requires explicit events. Even stock-flag candidates require reward/ownership separation before campaign activation; receiving an item must never create a location check. The dormant bridge can stage `CampaignJournalState` selections and restores, but the ledger still has no production caller or live-session observation path.

The current mod uses the catalog dispatcher for its two validated checks and the native inventory model for its five validated first moves. It does **not** activate every entry. The new `CampaignSeed` interface is an internal, tested contract, not an importer for `.chunky`, randomized ROMs or original AP `slot_data`. Every declared edit requires a corresponding implemented handler. Its hook set must come from trusted compiled code, never a seed or server assertion.

`CampaignSeed` hashes the complete canonical validated manifest and retains the first 128 bits as its game-save binding. Unknown top-level fields are rejected, so an option cannot be silently accepted while omitted from the binding or gameplay capability checks. Array order is part of this exact manifest identity; the future exporter must emit one deterministic order. `CampaignReceipts` reconciles a durable received-item prefix against a fixed-width, offset-checked 32-byte logical game-save header containing that binding, a 16-bit applied-item counter and a canonical CRC-32, matching the counter width of the original randomizer's `DATA_APCOUNTER` while detecting corruption or a torn trailer write. An all-zero header remains unbound, a different seed binding and a counter ahead of the durable journal fail closed, and the receipt at exactly the saved counter is replayed until the game advances it. Restoring an older game save intentionally replays the missing suffix because its item effects and counter must have been restored together.

`native/campaign_journal.cpp` now owns the dormant full-campaign disk state. Its exact seed binding, indexed AP receipt list and canonical observed-location list are validated completely before publication. Receipt overlap is deduplicated, while gaps, rollback, conflicting history, invalid fields and oversized updates fail closed. Game observations are restricted to the selected set and merged additively. Every changed snapshot reaches the atomically replaced journal before becoming visible in memory. `CampaignChannel` queues one receipt/check mutation at a time, performs validation and atomic persistence on its worker, and publishes completion plus the durable receipt count/check set only afterward. Rejected updates retain the prior snapshot. `CampaignProtocol` validates original-world room identity, slot/version and the exact checked/missing partition, then uses that channel for Sync recovery, receipt overlap and durable check resend. `CampaignSession` runs it through the same bounded direct WebSocket/TLS transport policy as the test profile. Given a valid EEPROM identity, the channel derives only the exact committed receipt prefix and check restore set needed by the MIPS staging APIs; an unbound save yields no stage, and a corrupt, foreign, ahead or unsupported prefix is rejected. These v3 exports are packaged but have no production MIPS caller, so no current game path starts the session.

`ap_campaign_stage_wire` is the fixed native/game boundary for that derived snapshot: magic and format, sealed identity, complete selected and observed bitsets, a bounded count, the optional next durable item and up to 4096 applied item IDs. `CampaignChannel` loads and owns the journal on a worker, queues identities through a nonblocking request handoff and reduces each accepted request off the game thread. The bridge validates the complete variable-length RDRAM span, identity, count, bitsets, subset relation and flag/shop aliases before its first write, then emits N64-order fields with explicit retry, unbound, rejected and unavailable results. The linked MIPS consumer preflights the complete wire and reducer before publishing its dormant ledgers and either a pending transaction or an explicit caught-up state. Malformed data cannot replace a successful publication. The ABI is packaged but has no MIPS import or production caller yet.

`mod/campaign_transaction.c` proves the next receipt against the exact staged prefix. For every supported catalog item it emits a fixed 584-byte record containing the current and sealed `counter + 1` identities, the item ID, effect classes, and complete before/after inventory snapshots. It distinguishes idempotent ownership, counted resources, one-shot traps and no-op receipts; combined effects retain every applicable class. Unknown and 19 explicitly unsupported definitions, corrupt identities, counter overflow, misalignment, stale saves and foreign bindings fail without changing the previous publication.

`mod/campaign_items.c` is the receipt-derived counterpart to the original randomizer's separate `CountStruct`. It exposes bounded count/ownership queries for Kongs, keys, hints, blueprints, company coins, bean, abilities, moves, shopkeepers and counted resources, plus safe lookup of catalogued item flags. The publication is accepted only from the exact staged inventory while every capability is disabled. Every query requires its private item capability and revalidates file zero plus the complete current trailer, so a save restore, receipt advance or foreign binding makes it unavailable immediately. It never writes randomizer-added flags into the stock permanent-flag block. Original camera, shockwave, vines, barrels, diving and oranges checks read this publication through the exact `hasFlagMove` call sites. The original `requirement_item` ABI is also adapted at every pinned `getItemCount_new` site, and all six `getKongOwnershipFromFlag` sites use the five canonical Kong flags. These cover pause/file percentage, Snide blueprint status/counts, balloon/small-item ownership, fairy capacity and K. Lumsy key iteration. Gameplay adapters convert unavailable/invalid queries to zero while the diagnostic API retains `-1`. The item capability has no production caller and remains disabled; these additional hooks do not acknowledge Kong, key or counted receipts.

The same module now executes 148 catalog definitions while `MOVES|SAVE|ITEMS` is active at an exact safe adventure/file/player context. It projects moves, guns, instruments, progressive upgrades, abilities, Kongs, keys, permanent flags, specials, hints, blueprints and counted resources from the durable receipt prefix; No Item advances without a gameplay mutation. Low ownership bits are replaced while unrelated high bits are retained, permanent flags use the stock flag writer, and instrument ownership raises melon capacity idempotently. Golden Bananas reproduce the original AP client's balanced live distribution, and Rainbow Coins add five live coins to every Kong; randomizer-only counts stay in the trailer-bound projection. With the additional `TRAPS` capability, 13 trap aliases execute Disable A/B/Z/C-Up or Dry after the original player, transition, map and movement safety checks. The four input traps mask the stock controller path for 240 frames; Dry clears stock ammo, oranges, crystals, film and live/saved instrument energy. The routine accepts only the exact currently published proof, stages the sealed next trailer, invokes the stock save entry point, and invalidates the consumed proof. Duplicate ownership/count receipts advance safely without repeating live grants, while each received trap receipt executes once. The other 17 trap definitions and 19 upstream metadata-only definitions are rejected before mutation. There is still no production caller or gate assignment, so this executable path remains dormant.

The game-side half of this contract now reserves the final 32 bytes of the isolated 2 KiB EEPROM image for that header. A guarded replacement for the real save writer reduces only its unused-tail clearing range by 32 bytes; the stock writer, offsets and CRC regions remain unchanged. The load path already restores the complete EEPROM image. The trailer has its own canonical CRC-32 because it lies outside the stock per-file and global CRC regions. It accepts only an all-zero initial binding at counter zero, an idempotent current counter, or an exact one-step advance for the same binding while the save capability is active. Corrupt state, seed changes, rollback, skipped counters and overflow fail closed. Gate-off execution remains byte-for-byte equivalent to the relocated stock writer and clears the trailer, preserving ordinary saves.

This storage and restart-reconciliation path is still dormant in gameplay. The direct campaign session can feed the journal, the bridge can prepare a validated snapshot, and the game can prove and execute every replay-safe/no-op receipt transition plus the five implemented trap behaviors. Randomizer-only ownership and counts advance in the same trailer/save transaction without inventing stock EEPROM fields; the query publication then fails closed until the advanced durable prefix is staged. A future game orchestrator must drive that lifecycle and dispatch the remaining one-shot traps before enabling the full capability set. A native sidecar acknowledgement would create a crash window and is deliberately not used. The campaign gate remains closed until the remaining trap mutations and lifecycle dispatch are executable and tested.

## Guarded gameplay replacements

Forty real game functions now have recomp replacements. Six cover independent special-move script conditions (including inversion), Strong Kong/Mini Monkey/Hunky Chunky/Orangstand Sprint barrels, Rocketbarrel, Pony Tail Twirl, Chimpy Charge/Orangstand/Primate Punch, and crystal-coconut move eligibility. Eleven functions reproduce the original randomizer's 22 camera/shockwave/training edits: six camera flags become the separate `0x2FD` flag and call the receipt query, the film-capacity path keeps its two original NOP edits, and shockwave plus all training abilities call the same query. Eleven further functions contain the complete pinned item-count and Kong-ownership query edits described above. Unknown flags and gate-off execution retain stock permanent-flag behavior; the randomizer-only camera flag is false while disabled, and mapped ownership fails closed when the staged receipt identity is stale. One replacement intercepts positive golden-banana awards while retaining collection-flag and HUD effects. It neither increments nor clamps received inventory. This is only the GB reward path, not full item replacement.

Three shop functions implement the original low-level move changes: current-world selection, independent move ownership tests, cross-Kong move/gun/instrument purchases, shared upgrades, and separate Kong/price bytes for affordability and payment. Relocatable legacy move tables start empty and can only be prepared through an internal, validated loader while the gate is off. The original hook's runtime instruction write is replaced with an empty-shop control-flow path.

Those three functions also dispatch to separate AP handlers when the internal shop capability is set. `mod/ap_shops.c` covers all 120 AP shop IDs: 100 Kong-specific and 20 shared checks, including Isles Cranky. It selects only configured locations, checks the original cumulative coin threshold without deducting it, revalidates the offer at purchase time, and records only the AP check. It does not grant a vanilla item, refill resources or write new shop flags into stock save storage. A fourth shop-function replacement preserves the original vendor-specific purchase animations for the AP item type.

The AP shop plan rejects duplicate/inactive/non-shop IDs, invalid prices and mixed shared/individual offers. `CampaignSeed` requires a `shops` array with exactly one `{ "location": AP_ID, "price": 0..255 }` entry per selected shop; missing prices never default to free. Game snapshots retain observed checks without destructive polling; restored snapshots are validated atomically and can only add checks. These APIs are internal and **not yet connected to durable campaign transport**. Their game-local state alone does not survive restarting the process. The ordinary game-save call does not persist this separate AP ledger. First-move gifts, delivery of resolved scout/recipient data into gameplay, shop hints, Jetpac randomizer behavior and general receipt notifications remain unported, so the seed's full `shops` capability requirement is not satisfied yet.

Three further replacements provide AP offer dialogue, post-purchase completion and a private text bank. `mod/shop_text.c` prevents AP item type 21 from indexing stock move-dialogue arrays. It shows generic AP affordability text with the existing coin/price HUD, uses the original randomizer's generic-item explanation after a recorded purchase, waits for dialogue and animation completion, restores player/level state and requests the next offer. Stale/rejected purchases return to selection without success text or an intro-flag write. Only the actual vendor's stock intro flags can be written. Empty shops and non-AP dialogue retain stock behavior; this is not the original seed-specific shop hints/presentation implementation.

The private text bank ships inside the mod, with the stock parsed-text structure and a reserved 16-bit file ID. It never reads nonexistent randomized-ROM text entries or enters the heap-owned text cache. Its immutable storage remains valid for queued dialogue even if the gameplay gate changes. Ordinary file requests still run the relocated stock loader and preserve its reference counts. This bank currently contains English text for the supported US ROM.

`mod/shop_overlay.c` replaces the purchase overlay updater for AP shop items, preventing type 21 from indexing the stock five-entry item-name table. It preserves the original actor PAAD allocation and uses a separate bounded pool for up to eight simultaneous immutable label snapshots. The original AP fade timing works across durations 50–255 frames (default 130), including short-duration fades. Item and recipient lines use the original fonts, matrices and opacity commands. Expiry, gate changes, map changes and shop-plan replacement dismiss tracked AP overlays; actor address reuse starts a fresh snapshot. Non-AP overlays keep the relocated stock behavior.

The internal `ap_apshop_set_labels` API validates complete replacement snapshots before publishing: only selected shops, unique IDs, canonical terminated text, uppercase ASCII letters/digits/spaces, zero reserved fields and valid durations. An empty snapshot clears old-room names, while displayed strings cannot change underneath an already active overlay. `native/presentation.hpp` prepares bounded item and `TO <recipient>` labels, removes unsafe formatting characters and uses explicit fallbacks for names with no supported glyphs. It omits unsupported Unicode glyphs rather than transliterating them. No label data grants an item or reports a check. A committed shop check with no label displays `ARCHIPELAGO CHECK / ITEM DETAILS PENDING`.

`native/scouts.cpp` implements the live AP metadata side. It requests only session-selected locations with `create_as_hint: 0`, validates the complete `LocationInfo` batch, keys item IDs by the receiving slot's game, uses aliases only from the configured team, requests only required data packages, binds each package to the checksum advertised in `RoomInfo`, and clears all metadata on reconnect. Bounds cover games, slots, names, message sizes and selected locations. Malformed or conflicting replies cannot partially publish a replacement snapshot and cannot touch checks, receipts, inventory or the journal.

`dk64_ap_labels_v2` copies canonical label snapshots directly into RDRAM. It validates the output span and capacity, serializes the fixed layout in N64 byte order, returns explicit invalid-bounds and retry results, and uses a nonblocking worker snapshot so the frame thread retries rather than waiting. `mod/ap.c` applies complete snapshots through `ap_apshop_set_labels`, including empty snapshots while reconnecting so old-room names are cleared. This consumer remains behind `AP_GAMEPLAY_SHOPS`, whose campaign gate is still zero. The current session resolves two non-shop test locations, so its exported label snapshot is empty. The reusable processor is tested with all 120 shop IDs, but campaign-selected shops are not yet loaded into the live session. This is purchase presentation metadata, not pre-purchase hints or the general received-item notification queue.

Two save functions implement the original three-bit move representation: write independent moves to the unused three-bit character field (category 10), prevent the old field from overwriting it, and restore it to the move byte when loading. A third guarded save-writer replacement preserves the 32-byte campaign trailer only when `AP_GAMEPLAY_SAVE` is active. The trailer stores the seed binding, applied-item counter and its own checksum in the already isolated DK64 save slot 1 image. It does not persist the separate AP check ledger, apply items or activate campaign delivery. Do not migrate an existing normal/test save by toggling the gate.

`mod/gameplay-patches.json` pins the prepared US ROM, individual function bodies, and original patch sources. `tools/lift-gameplay.py` creates relocatable original/patched copies with local jump tables and hook continuations. Functions and calls are resolved within their source overlay so shared menu/other-overlay virtual addresses are not confused. Symbol loads and halfword edits are transformed at build time. Unknown indirect jumps, ambiguous calls, changed source functions and out-of-function branches fail the build. Normal builds generate these bodies into `build/mod/`; the source archive contains the transformation and manifest, not the ROM or extracted bodies.

An internal capability gate remains zero in the integration-test profile. It has no user setting or exported activation API. Off mode executes the relocated original function; campaign behavior must not be enabled until the remaining receipt executors, lifecycle orchestration and all required world hooks are implemented. Reconnect cannot enable it.

The source inventory currently covers 86 C files (26,820 lines) and 1,761 Python calls to `writeValue`, `writeFunction`, `writeHook`, `writeFloat` and `writeLabelValue`. ## Reproduce and verify

In a separate local upstream checkout, select the pinned revision, including `archipelago`, `randomizer` and `base-hack`. From the parent port workspace:

```powershell
python archipelago/tools/import-randomizer.py .local/dk64-randomizer-source
python archipelago/tools/verify_upstream.py .local/dk64-randomizer-source
```

The catalog compiler reads whitelisted Python AST literals; it does not execute the upstream generator/client. Generated catalog/header/coverage files ship with the source archive, so ordinary builds do not require the randomizer checkout. The verification command regenerates into temporary storage and compares all three files. Gameplay builds now also require the user's correctly prepared US ROM, as described in the parent port's ROM preparation instructions; mismatched ROMs are refused.

After building the mod, run the executable gameplay tests from `archipelago/` in WSL. Build the pinned upstream test utility once with `cmake --build ../.local/host-tools-wsl --target OfflineModRecomp -j4`, then run `bash tools/test-gameplay.sh`. During item-query development, `AP_GAMEPLAY_TEST=campaign-items bash tools/test-gameplay.sh` runs only that focused slice. These tests also require the prepared port's `upstream/RecompiledFuncs` for original-function baselines. No emulator, game save, AP room or device is changed by them.

Host CTest exercises all location IDs, detector classification, shop alias rejection, atomic confirmation, independent move ownership, item totals, metadata tampering, cross-game item-ID collisions, team aliases, all 120 shop-label outputs and seed requirements. Campaign journal fixtures additionally force the atomic writer's temporary path to fail and prove that neither receipts nor checks publish after a failed disk commit. Native networking tests verify scouting against both a fault server and the isolated real AP 0.6.7 server; they simulate game events and do not prove collection or item effects inside DK64. The Android native library and MIPS mod can build successfully while these campaign hooks remain unfinished.
